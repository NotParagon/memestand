# MemeStand.com: refresh and deploy runbook

Static site. Plain HTML/CSS; the only JavaScript is the Cloudflare Web Analytics beacon (see below). Everything is generated from JSON.

> **Keep the analytics snippet.** Every HTML page carries the Cloudflare Web Analytics beacon just before `</body>`
> (`CF_ANALYTICS` in build.py, added by `footer()`). It is cookieless, aggregate-only, and disclosed on /privacy.html.
> Don't remove it, don't duplicate it, and any new page template must end with `footer()` so it gets the snippet.
> Check after each build: every `*.html` must contain it exactly once
> (`rg -c 'static.cloudflareinsights.com/beacon.min.js' --glob '*.html' --glob '!raw/**'`). The token is a public beacon token.
> If you change what analytics or scripts the site uses, update the privacy text in `build_privacy()` and `PRIVACY_UPDATED` first.

```
memestand/
  build.py                   data/memes.json -> the whole site (all HTML + feed/sitemap/robots/llms.txt)
  index.html                 generated homepage, don't hand-edit
  top-memes-today/ trending-memes-this-week/ best-memes-this-month/   generated single-list pages
  archive/YYYY-MM-DD.html    generated "Daily Meme Report" for each day; archive/index.html lists them
  about.html                 generated about + ranking-method page
  feed.xml sitemap.xml robots.txt llms.txt   generated each build
  favicon.ico favicon.svg apple-touch-icon.png og-default.png   static icons (tools/make_icons.py, one-time)
  CNAME .nojekyll            GitHub Pages config, keep
  data/candidates.json       research notes: every candidate meme + its evidence
  data/memes.json            generated by tools/rank.py: the three ranked Top-10 lists
  data/archive/YYYY-MM-DD.json   build.py's per-day snapshot of memes.json (source of the archive pages); COMMIT, never delete
  images/                    local thumbnails (<= 400px everywhere, EXIF/metadata stripped), named <id>.jpg
  data/blocklist.json        takedown/DMCA blocklist (see "Legal rules"); never delete entries
  tools/legal.py             blocklist matching, content exclusions, headline-neutrality check, credit lines
  terms.html privacy.html dmca.html   generated legal pages (text + LEGAL settings live in build.py)
  tools/fetch_reddit.py      pulls Reddit top-of-period RSS feeds into raw/
  tools/rank.py              scores candidates, picks the top 10 per period, downloads thumbnails
  raw/                       scratch research data (Reddit RSS, KYM metadata); not deployed
  preview.png                screenshot of the current build
```

## Daily refresh (about 20 minutes for an agent, run once a day, e.g. 6:00 AM PT)

1. **Gather evidence** (all free and anonymous; no API keys, no logins):
   - **X**, via Grok Bot's built-in public X reads (`x` namespace):
     - `search_news` with "meme" / "viral meme" / "memes trend" (max_age_hours 24 / 168 / 720). These are the X trending stories about memes.
     - `search_posts_all` (sort_order=relevancy, last 24h) for each story's key phrase. Record the best post's `like_count` / `impression_count`.
     - Re-check the existing posts with `get_posts_by_ids` to confirm they still exist and to refresh their numbers.
   - **Reddit**: `python3 tools/fetch_reddit.py --force`
     - Pulls r/memes and r/dankmemes top-of-day, week, and month RSS into `raw/` and `raw/reddit.json`.
     - It auto-backs off on 429s, so a full run takes about 3 minutes.
   - **Know Your Meme**:
     - Fetch with curl and a browser User-Agent (WebFetch returns empty pages):
       - `https://knowyourmeme.com/` ("Popular right now", "Top Entries This Month")
       - the latest "Weekly Meme Roundup" editorial
       - the monthly "Meme of the Month" poll
     - From each entry page, take:
       - `og:image` (thumbnail)
       - `article:published_time` (first_seen)
       - page views: `<dd class='views' title='N Views'>`
       - the view and like counts the entry cites
2. **Edit `data/candidates.json`**:
   - Add new memes and update the numbers on existing ones.
   - Set `periods` to the lists each meme qualifies for:
     - `daily`: took off in the last ~36h
     - `weekly`: active in the last 7 days
     - `monthly`: active in the last 30 days
   - Remove memes that have aged out of every window.
   - Every candidate must have a real, opened source URL. Never invent memes, numbers, or links.
   - Follow "Legal rules" below for every headline, image, and flag. Read rank.py's `EXCLUDED` / `BLOCKED` lines and fix or accept them.
3. **Rank, fetch thumbnails, build:**
   ```bash
   cd memestand
   python3 tools/rank.py          # prints the three lists with scores, writes data/memes.json, downloads images/
   python3 build.py               # writes the whole site + today's archive snapshot (the "Updated" stamp is in PT)
   google-chrome --headless=new --no-sandbox --hide-scrollbars --window-size=1280,2600 \
       --screenshot=preview.png "file://$PWD/index.html"
   ```
   - To refresh a changed thumbnail, delete `images/<id>.jpg` first. `rank.py` only downloads missing images.
   - Never delete old `images/*.jpg`, `archive/*.html` or `data/archive/*.json`: past archive pages still use them.
     The one exception is a takedown, and the blocklist handles that automatically.
   - Validate before pushing (see "SEO checks" below).
4. **Verify links**:
   - curl every KYM and Reddit URL in `data/memes.json` and expect a 200.
   - Check X posts with `get_posts_by_ids`. A missing post means it was deleted, so drop it.
5. **Write meme pages for new memes** (see "Meme pages" below):
   - `build.py` prints `! meme pages still need explainer/origin text ...` for every new meme. For each listed slug, fill in
     `explainer`, `origin`, `sources`, `status` (and `kym_url` when one exists) in `data/meme_pages.json`, then run `python3 build.py` again.
   - Don't rewrite entries that already have text unless a fact was wrong. Text is written once and reused.
6. **Deploy**:
   ```bash
   git add -A && git commit -m "Daily update $(TZ=America/Los_Angeles date +%F)" && git push origin main
   ```
   `git add -A` matters: each day adds a new `archive/<date>.html` and `data/archive/<date>.json`.
   GitHub Pages rebuilds in about a minute (`gh api repos/NotParagon/memestand/pages/builds/latest --jq .status` should say `built`).

### Ranking method (virality evidence score, in `tools/rank.py`)

| Signal | Points |
|---|---|
| Reach of the best post or compilation (X API impressions, or views cited by KYM) | 10 × log10(views); e.g. 1M = 60, 10M = 70 |
| Only likes known | 10 × log10(likes × 10) |
| Reddit top-feed position (Reddit hides vote counts from anonymous feeds) | r/memes #1 = 62, r/dankmemes #1 = 60, −2 per rank |
| Each additional platform with confirmed spread | +5 (max +10) |
| Documented on Know Your Meme | +5 |
| Picked in a KYM Weekly Roundup or Meme-of-the-Month poll | +3 |
| X News trending story about it | +5 |
| KYM page views ≥ 50,000 | +5 |

- The base is the max of the reach signals that apply. The bonuses reward cross-platform spread, which is the best sign that a meme is a real meme and not one viral post.
- Ties keep candidate order.
- A meme may appear in more than one list. Big ones usually do.
- The daily #1 becomes the red top story.

## Deploying with the GoDaddy domain

| Option | Cost | DNS work at GoDaddy | Daily-update path |
|---|---|---|---|
| **A. GitHub Pages** (recommended) | Free | Add 4 `A` records for `@` (185.199.108.153, .109.153, .110.153, .111.153) + `CNAME www → <user>.github.io` | `git commit && git push`; live in about 1 minute, free HTTPS |
| B. Cloudflare Pages | Free | Change the nameservers at GoDaddy to Cloudflare's (DNS then managed in Cloudflare) | `npx wrangler pages deploy . --project-name memestand` with an API token |
| C. Netlify | Free tier | Netlify DNS, or `A @ 75.2.60.5` + `CNAME www` | `netlify deploy --prod` with a token |
| D. GoDaddy cPanel / Web Hosting | About $6–12/mo extra | None (same account) | Upload by FTP/SFTP (`lftp mirror -R`) using hosting credentials |

**Recommendation: A, GitHub Pages.** It is free, gives automatic HTTPS, and handles static traffic spikes well.

- The domain stays at GoDaddy and only needs DNS records added. Nameservers don't move.
- The daily refresh becomes a single `git push`. That is the easiest thing for an automated job to do reliably.
- Cloudflare Pages is an equally good choice if you'd rather move DNS to Cloudflare, since it also adds CDN and analytics.
- Avoid paying GoDaddy for cPanel hosting just to serve a static page.

One-time setup (needs Roger's accounts, nothing has been changed yet):

1. Create a GitHub repo, e.g. `memestand`, and push this folder. `raw/` can be excluded.
2. Enable Pages: Settings → Pages → Deploy from branch `main`, root. Set the custom domain to `memestand.com` and tick Enforce HTTPS.
3. In GoDaddy:
   - Go to My Products → memestand.com → DNS.
   - Delete the default "Parked" `A @` record.
   - Add the four `A @` records above and `CNAME www → <github-user>.github.io`.
4. Wait for DNS (minutes up to about 1 hour), then the site is live at https://memestand.com.

Content note: thumbnails are small, attributed, and link back to the original post. See "Legal rules" below.

## SEO and AI-assistant discovery (all automatic in build.py)

Every `python3 build.py` regenerates all of this from `data/memes.json`, so no manual SEO step is needed each day:

- **Head tags** on every page: keyword title, meta description naming today's #1, canonical `https://memestand.com/...`,
  Open Graph + Twitter `summary_large_image` (og:image = today's #1 local thumbnail as an absolute URL, or `og-default.png`
  when #1 is a text card), favicon links, Atom feed link, `lang="en"`.
- **Headings**: one `<h1>` per page (masthead + tagline), `<h2>` "Top 10 Memes Today / This Week / This Month", `<h3>` per meme.
  Alt text on every image is "<Title-Case headline> meme - #N today on MemeStand".
- **JSON-LD** (`@graph`): Organization, WebSite, CollectionPage (dateModified = build time), and an ItemList per top-10 list
  (ListItem position / name / url / image). Archive pages add datePublished and a BreadcrumbList.
- **Pages**: `/top-memes-today/`, `/trending-memes-this-week/`, `/best-memes-this-month/` (with the evidence notes),
  `/archive/YYYY-MM-DD.html` (one per day; same-day rebuilds overwrite only today's), `/archive/`, `/about.html`.
- **Crawl files**: `sitemap.xml` (lastmod per URL), `robots.txt` (allows everyone incl. GPTBot, OAI-SearchBot, PerplexityBot,
  Google-Extended, ClaudeBot, Applebot-Extended, CCBot...), `llms.txt` (site summary + today's three lists in Markdown),
  `feed.xml` (Atom, newest 60 daily #1s).
- The old 30-minute `<meta http-equiv="refresh">` was removed: content changes once a day, and Bing and accessibility
  guidelines treat timed refreshes as a negative. Don't add it back.
- Headline title-casing for titles/descriptions uses `ACRONYMS` / `SPECIAL` in build.py; add a word there if one comes out wrong (e.g. "Gpu").

### SEO checks (run before each push; takes seconds)

```bash
python3 build.py && python3 build.py && git status --short   # 2nd run must change nothing beyond the 1st (idempotent)
python3 - <<'PY'
import json, pathlib
from lxml import etree, html
for p in pathlib.Path('.').rglob('*.html'):
    if 'raw' in p.parts: continue
    d = html.fromstring(p.read_text())
    [json.loads(s.text) for s in d.xpath('//script[@type="application/ld+json"]')]   # raises if JSON-LD is broken
    assert len(d.xpath('//h1')) == 1 and all(i.get('alt') for i in d.xpath('//img')), p
etree.parse('sitemap.xml'); etree.parse('feed.xml')
print('ok')
PY
```
After pushing: `curl -s https://memestand.com/ | grep -c 'application/ld+json'` should print 1.

## Meme pages (`/meme/<slug>/`, `/memes/`, store: `data/meme_pages.json`)

Every meme that has ever ranked gets a permanent page at `https://memestand.com/meme/<slug>/`. The H1 is
"<Meme name> meme: what it means and where it came from". The page shows the thumbnail, "What it means", "Origin",
first- and last-seen dates on MemeStand, the best rank per list, links to every archive day it appeared on, sources and related memes.
`/memes/` is the A–Z index. Every headline on the home, period and archive pages links to the meme page; the thumbnail
and "View original" still link to the source. The pages are also listed in `sitemap.xml` and `llms.txt` automatically.

**Store format** (`data/meme_pages.json`, keyed by slug, sorted; build.py rewrites it deterministically):
```json
"sam-altman-ram": {
  "name": "Sam Altman RAM",            // display name; the H1 adds " meme" unless the name ends in meme(s)/trend
  "ids": ["altman-ram"],                // candidate ids that map to this page
  "status": "full",                     // "full" = explanation + origin backed by sources; "short" = only what the source shows
  "source_url": "...", "kym_url": "..." or null,
  "explainer": "1-2 short paragraphs (blank line between paragraphs)",
  "origin": "1-2 short paragraphs",
  "sources": [{"name": "The Verge: ...", "url": "..."}],   // every source the text relies on (the ranked post is added automatically)
  "related": ["other-slug"],            // optional; build.py adds memes that shared the same lists
  "written": "YYYY-MM-DD"
}
```
- **Slugs are permanent.** build.py makes a slug from the meme's name (or id), dedupes it (`-2`, `-3`) and stores it. Never rename a slug or
  reuse one for a different meme. If a meme returns under a new candidate id, add that id to the existing entry's `ids` instead of making a new page.
- Optional candidate fields `name`, `explainer`, `origin` and `kym_url` in `data/candidates.json` pass through `rank.py` into `memes.json`,
  and build.py copies them into an empty store entry. They never overwrite text already in the store.
- **How to write them** (same rules as "Legal rules" below):
  - Use only facts in the data or in a source you actually opened: the ranked post, the KYM entry, or a primary source (transcript, the post itself).
    List each one in `sources`. Link the original post or KYM.
  - "What it means" is your own short, original explanation (don't copy KYM text). Explain the joke format and how people use it.
  - "Origin" is neutral and factual: who posted what, where, and when, per the source. **Never invent an origin.** If it isn't documented,
    say what the ranked post shows and that MemeStand has no further origin information, and set `"status": "short"`.
  - No unverified claims about real people. Frame allegations as allegations attributed to their source ("per KYM"). Don't name private
    people or people only connected to an allegation. Quote real people only from the primary source.
  - Don't publish Roger's full name or address, and don't use the Drudge name.
- `FAQPage` JSON-LD is added only for `"status": "full"` pages. Short pages say they are deliberately short.
- Blocked memes (`data/blocklist.json`) get no page: build.py drops their store entry and deletes `meme/<slug>/`. Archive pages are never deleted.
- og:image on meme pages follows `OG_USE_MEME_THUMB` (currently off, so `og-default.png`).

## Legal rules (enforced in tools/legal.py, tools/rank.py and build.py; follow them on every refresh)

Not legal advice. These rules keep the site's copyright, defamation and content risk low. They live in code so they survive rebuilds.

**1. Takedowns / DMCA: `data/blocklist.json`**
- When a takedown request or DMCA notice arrives (GitHub issue or email), act within 1-2 days. Add an entry to `entries`:
  `{"id": "<candidate id>", "url": "<source or image URL>", "title_contains": "...", "reason": "DMCA notice from X", "date": "YYYY-MM-DD"}`
  Any one of `id`, `url` / `urls`, or `title_contains` is enough; use the most specific one.
- Then run `python3 tools/rank.py && python3 build.py` and push. rank.py drops the candidate from candidates.json and deletes its thumbnail.
  build.py replaces the item with "[REMOVED IN RESPONSE TO A TAKEDOWN REQUEST]" on every page, archives included, and scrubs it from `data/archive/*.json`.
- Never remove a blocklist entry unless a valid counter-notice restored the item (process on /dmca.html). Keep a private log of notices
  (date, sender, item, action) outside the public repo.
- The image stays in git history. For a serious claim, Roger can rewrite history or ask GitHub Support.
- Repeat-infringer rule: if one source account gets 2+ valid notices, stop featuring that account (add its posts and/or a note in candidates).

**2. Headlines must be neutral and attributed**
- Headlines describe the meme and the reaction, not facts about people. Don't write "X DID Y" about a real person unless it is a documented,
  verifiable fact, and even then attribute it ("PER KYM", "PER <outlet>").
- Allegations (affair, cheating, fraud, crime, abuse, racism...) must be framed as allegations, with the source:
  `H3'S ETHAN KLEIN CHEATING ALLEGATIONS SPAWN A MEME FACTORY, PER KYM`, not `ETHAN KLEIN AFFAIR SCANDAL`.
- Quote what people actually said, verified at the primary source (transcript, the post itself). Don't paraphrase it into something stronger.
- Label jokes as jokes: `X USERS JOKE THAT KEN PAXTON 'EATS SALSA...'`, `ELON MUSK JOKES ABOUT...`.
- rank.py **excludes** a candidate whose title or card text uses an allegation word without an attribution word (per / alleged / accused /
  memes about / jokes / reportedly...). Set `"headline_reviewed": true` only after you have checked the wording against these rules.
- Notes ("Why it ranks") follow the same rules.

**3. Content exclusions** (also published on /about.html#policy)
- Add `"flags": [...]` to a candidate to exclude it: `nsfw`, `sexual`, `hate`, `demeaning` (mocks race, ethnicity, national origin,
  religion, sex, orientation, gender identity, disability), `minor`, `graphic`, `self-harm`, `harassment`, `doxxing`, `private-person`, `defamatory`.
  Add a `flag_note` explaining why.
- Automatic: hard terms (nsfw, porn, nude, gore, suicide, doxxing...) exclude a candidate. Words suggesting a child (kid, teen, baby,
  "12-year-old"...) exclude it until you confirm no minor is the subject and set `"minor_reviewed": true`.
- Never feature memes about a private individual who didn't choose publicity (random people filmed in public, leaked DMs) unless
  they have clearly embraced it. When in doubt, leave it out.

**4. Images and attribution**
- Thumbnails: max 400 px on the longest side, re-encoded JPEG with EXIF/GPS/ICC metadata stripped. rank.py enforces this on every run for
  all files in images/ (`normalize_images`), so never commit a larger or raw image.
- Every item shows a credit line ("posted by u/<user> on r/<sub>", "posted by @handle on X", "image via Know Your Meme") plus "View original".
  rank.py fills it in automatically (Reddit authors from raw/reddit.json). Set `"credit"` on a candidate to override it, e.g. with the real creator.
- `"image_policy"` per candidate: `local` (default, small thumbnail), `hotlink` (show the platform's own image URL, nothing stored here; use it
  for professional or agency photos), `none` (text card only; use it for paparazzi or stock photos, screenshots of private messages,
  or anything a rights holder is sensitive about).
- Social preview cards (og:image) use our own `og-default.png`, not someone else's meme (`OG_USE_MEME_THUMB = False` in build.py).
- Don't add other JavaScript embeds (X widgets.js etc.) without first updating /privacy.html: they set third-party cookies.
  The Cloudflare Web Analytics beacon is the only allowed script (cookieless, disclosed on /privacy.html).

**5. Names and trademarks**
- Use X, Reddit, Know Your Meme only to name sources. Never imply partnership, and never use their logos.
- Don't call the site "Drudge-style" or use the Drudge Report name.
- The footer non-affiliation line and the "memes (c) their respective owners" notice are generated. Keep them.

**6. Legal page settings** (`LEGAL` dict at the top of build.py)
- `contact_email` / `dmca_email`: None, so pages point to GitHub issues. Once Roger creates legal@ / dmca@memestand.com, set them and rebuild.
- `dmca_agent_registered`: set True after Roger registers the DMCA designated agent at https://dmca.copyright.gov (renew every 3 years).
- `governing_law`: "California" is a placeholder until Roger confirms it.
- Never publish Roger's full name, home address or phone on the site.
