# MemeStand.com: refresh and deploy runbook

Static site. Plain HTML/CSS; JavaScript is the Cloudflare Web Analytics beacon plus a tiny first-party inline script that shows a relative "Updated … ago" stamp (see build.py). Everything is generated from JSON.

> **No layout shift:** every `<img>` must always have explicit `width`/`height` (build.py's `wh_attrs()` reads them from the file with PIL) or a CSS `aspect-ratio` box, so space is reserved before it loads (CLS).

> **Theming (light/dark):** all colors in build.py's `CSS` are CSS custom properties (`--bg`, `--fg`, `--red`, `--link`...) defined in `:root`, with dark values via `prefers-color-scheme` and `[data-theme=dark|light]` overrides. Use the variables for any new color, never hex literals. The header toggle (`THEME_TOGGLE`, fixed 34px, absolutely positioned) saves the choice in localStorage; `THEME_HEAD` applies it before paint.

> **Keep the analytics snippet.** Every HTML page carries the Cloudflare Web Analytics beacon just before `</body>`
> (`CF_ANALYTICS` in build.py, added by `footer()`). It is cookieless, aggregate-only, and disclosed on /privacy.html.
> Don't remove it, don't duplicate it, and any new page template must end with `footer()` so it gets the snippet.
> Check after each build: every `*.html` must contain it exactly once
> (`rg -c 'static.cloudflareinsights.com/beacon.min.js' --glob '*.html' --glob '!raw/**'`). The token is a public beacon token.
> If you change what analytics or scripts the site uses, update the privacy text in `build_privacy()` and `PRIVACY_UPDATED` first.

## Daily refresh (HOURLY 6 AM-9 PM PT since Nov 4, 2026; keep each run well under an hour)

> Cadence (hourly 6 AM–9 PM PT since Nov 4, 2026): the routine runs every hour on the hour. 6 AM is the full refresh, 9 PM locks the day's archive, and every other hour is a light intraday re-rank under the same intraday rules. Hourly runs always rebuild and push so the 'Updated' stamp stays fresh (the header shows 'Updated X ago'; the about page and llms.txt say hourly 6 AM-9 PM PT). Mind the X read budget: light re-checks hourly, deep discovery at 6 AM. This repository does not schedule that cadence and does not publish social posts. Social clips are a separate routine; see "Social posts" below.

Site content refreshes on a fixed Pacific-time cadence so the home page and rankings stay current
through the day. Agents (or a human) should run this checklist at about:

| PT clock | Role |
|----------|------|
| **6:00 AM** | **Main daily refresh.** Full evidence gather, rewrite `candidates.json` `as_of` for today, rank + build, fill new meme-page explainers, deploy. |
| **9:00 AM** | Intraday re-rank. Pull fresh evidence; update metrics / add anything that clearly took off since 6 AM; age out as needed. Deploy only if the ranked lists or lead meaningfully change (no no-op commits). |
| **12:00 PM (noon)** | Intraday re-rank. Same rules. |
| **3:00 PM** | Intraday re-rank. Same rules. |
| **6:00 PM** | Intraday re-rank. Same rules. |
| **9:00 PM** | **Final lock for the day.** Re-rank once more, then leave today's `data/archive/YYYY-MM-DD.json` and `archive/YYYY-MM-DD.html` as the official end-of-day top 10. Do not rewrite that day's archive snapshot after 9 PM. |

Each run should finish within ~15 minutes of the hour above when practical. The header "Updated … ago" stamp
comes from the build timestamp in the visitor's browser (see build.py).

### Social posts (not in this repo)

Do not add a scheduler, a posting client, or social-card rendering to this repository. Refreshing the site does not publish anything, and it does not wait on a countdown rank or a locked morning top 5.

Posting is a separate routine on the operator's machine (its templates are not part of this repo). It now does two things:

- **New-entry singles**, about hourly from 6:30 AM to 9:30 PM Pacific. Only a meme's first entry into the daily top 10, with cross-day dedupe so the same meme is not posted again. The picture is on screen at the first frame, with the static red-M label and site name. No logo intro, no white intro, no end card, and no sung or spoken sting: render that still with the no-jingle option so the mix is the quiet instrumental bed alone.
- **One nightly recap**, resumed around 8 PM Pacific, in addition to those singles. This is not the old countdown. There is no white frame and no logo intro; the first meme (the visual #5) is on screen at the first frame, with its rank badge. The original bed and the sung Meme-Stand jingle play over that first meme, and the voice starts after the jingle. The voice delivers the description and the joke only. It does not say "number five" or any other rank, because the number is already in the picture. The end card stays. Build it with the meme-first option, from the latest verified daily top 5 at recap time, not from a deprecated 6 AM locked list.

The noon and 6 PM countdown clips are not part of this routine. Leaving the no-jingle and meme-first options off keeps the older template defaults for anything still rendered that way.

**Intraday rules (9 AM / noon / 3 PM / 6 PM / 9 PM):**
- Re-check all six sources (X, TikTok, Instagram, Reddit, YouTube, KYM); refresh `ev` numbers; add only memes with **new verified evidence**.
- Keep `as_of` as today's date. Lead rotation still applies (`data/lead_history.json`); prefer not to churn the lead mid-day unless a clearly bigger new meme takes the daily #1 and passes the 7-day lead rule.
- Skip the git commit if nothing meaningful changed vs the currently published site.
- Never invent memes, numbers, or URLs. NSFW / legal rules still apply.

**Full checklist (every run; 6 AM is the heaviest):**
1. **Gather evidence** (all free and anonymous; no API keys, no logins):
   - **X**, via Grok Bot's built-in public X reads (`x` namespace):
     - `search_news` with "meme" / "viral meme" / "memes trend" (max_age_hours 24 / 168 / 720). These are the X trending stories about memes.
     - `search_posts_all` (sort_order=relevancy, last 24h) for each story's key phrase. Record the best post's `like_count` / `impression_count`.
     - Re-check the existing posts with `get_posts_by_ids` to confirm they still exist and to refresh their numbers.
   - **Reddit**: `python3 tools/fetch_reddit.py --force`
     - Pulls r/memes and r/dankmemes top-of-day, week, and month RSS into `raw/` and `raw/reddit.json`.
     - It auto-backs off on 429s, so a full run takes about 3 minutes.
   - **Know Your Meme**:
     - Fetch with curl and a browser User-Agent (WebFetch returns empty pages):
       - `https://knowyourmeme.com/` ("Popular right now", "Top Entries This Month")
       - the latest "Weekly Meme Roundup" editorial
       - the monthly "Meme of the Month" poll
     - From each entry page, take:
       - `og:image` (thumbnail)
       - `article:published_time` (first_seen)
       - page views: `<dd class='views' title='N Views'>`
       - the view and like counts the entry cites
   - **YouTube** (works directly; anonymous; verified on this box Nov 4, 2026):
     - `python3 tools/fetch_youtube.py` searches "meme", "memes", "meme trend", "viral meme", "#shorts meme" for uploads from
       today and this week, sorted by views, into `raw/youtube.json`. Look for a phrase that also shows up on KYM / X / Reddit.
     - `python3 tools/fetch_youtube.py --query "frutiger aero yams"` checks one candidate's phrase (this-week filter, by views).
     - `python3 tools/fetch_youtube.py --video VIDEO_ID` re-reads one video's exact views, title, channel and upload date
       (into `raw/youtube_lookup.json`). Only use a video that is clearly *about this meme* (title/description match), never a
       generic compilation. Under 10,000 views it doesn't score.
   - **TikTok** (individual posts only):
     - TikTok has no open trending list. The Creative Center (`ads.tiktok.com/business/creativecenter/...`) is a JS shell and its
       API answers `40101` (login required) from this box; don't spend time on it.
     - What works: `python3 tools/fetch_social.py --kym SLUG` reads every TikTok/Instagram/YouTube post a KYM entry embeds
       (views, likes, author, date from the page's `__UNIVERSAL_DATA_FOR_REHYDRATION__` JSON), or pass post URLs directly:
       `python3 tools/fetch_social.py https://www.tiktok.com/@user/video/ID`. "no itemStruct" = removed/private; skip it.
     - Check the KYM context of each embed: some are background (e.g. the aesthetic a meme riffs on), not the meme itself.
       Record the largest post that *is* the meme. If KYM cites a bigger count for a post we can't read, use it with
       `"via": "KYM-cited count"` and keep the biggest directly-read post as `largest_post_read`.
   - **Instagram** (indirect; likes only):
     - Logged-out Instagram pages hide plays. `fetch_social.py` fetches reels/posts with the `facebookexternalhit/1.1` User-Agent and
       parses `og:description` ("70K likes, 164 comments - user on November 2, 2026"). Likes are the signal (no plays).
     - Find posts the same way as TikTok: the KYM embeds (`--kym SLUG`), or a post URL cited on X/Reddit.
   - All three write raw files only; copy the numbers you use into `candidates.json` (see the `ev` schema below) with `checked` = today.
2. **Edit `data/candidates.json`**:
   - Add new memes and update the numbers on existing ones.
   - Set `periods` to the lists each meme qualifies for:
     - `daily`: took off in the last ~36h
     - `weekly`: active in the last 7 days
     - `monthly`: active in the last 30 days
   - Remove memes that have aged out of every window.
   - Every candidate must have a real, opened source URL. Never invent memes, numbers, or links.
   - Per-source evidence lives in `ev` (all optional; only what you actually read):
     - `ev.x`: `{url, views, likes, checked, via}` (legacy `peak_views` / `peak_likes` are still read as X)
     - `ev.tiktok`: `{url, views, likes, author, posted, checked, via}` (+ `largest_post_read` when `via` is a KYM-cited count)
     - `ev.instagram`: `{url, likes, author, posted, checked, via}`
     - `ev.youtube`: `{url, views, title, channel, checked, via}`
     - `ev.reddit`: `{sub: "memes"|"dankmemes", rank}`; `ev.kym`, `ev.kym_views`, `ev.kym_editorial`, `ev.x_news` as before;
       `ev.platforms` lists the sources with confirmed spread by full name ("X", "TikTok", "Instagram", "Reddit", "YouTube", "Know Your Meme").
     - Add the best TikTok/Instagram/YouTube post to `also` as e.g. `{"name": "TikTok / @user (10.4M views)", "url": ...}`.
   - Follow "Legal rules" below for every headline, image, and flag. Read rank.py's `EXCLUDED` / `BLOCKED` lines and fix or accept them.
3. **Rank, fetch thumbnails, build:**
   ```bash
   cd memestand
   python3 tools/rank.py          # prints the three lists with scores, writes data/memes.json, downloads images/
   python3 build.py               # writes the whole site + today's archive snapshot + today's lead (the "Updated" stamp is in PT)
   google-chrome --headless=new --no-sandbox --hide-scrollbars --window-size=1280,2600 \
       --screenshot=preview.png "file://$PWD/index.html"
   ```
   - To refresh a changed thumbnail, delete `images/<id>.jpg` first. `rank.py` only downloads missing images.
   - Daily history notes (New today, First time, movement since yesterday, N days at #1) are written by this build from `data/archive/`. Do not type them into the HTML.
   - Never delete old `images/*.jpg`, `archive/*.html` or `data/archive/*.json`: past archive pages still use them.
     The one exception is a takedown, and the blocklist handles that automatically.
   - Validate before pushing (see "SEO checks" below).
4. **Verify links**:
   - curl every KYM and Reddit URL in `data/memes.json` and expect a 200 (use a browser User-Agent; KYM and Reddit block bare curl).
   - Also curl every `sources[].url` you add to `data/meme_pages.json`. Anything that isn't a 200 gets replaced or dropped.
     x.com returns 200 even for deleted posts, so check X sources with `get_posts_by_ids` as well.
   - Check X posts with `get_posts_by_ids`. A missing post means it was deleted, so drop it.
5. **Write the meaning & origin explainer for every new meme** (see "Meme pages" below; this is required, not optional):
   - `build.py` prints `! WARNING: meme pages still need explainer/origin text ...` for every new meme, and
     `! WARNING: meme page <slug> is missing <fields>` for any page with a gap. For each listed slug, fill in `explainer`, `origin`,
     `origin_confirmed`, `how_to_use`, `sources`, `status`, `checked` (and `kym_url` when one exists) in `data/meme_pages.json`,
     then run `python3 build.py` again. The run is done only when no `! WARNING` lines about meme pages are left.
   - Research the origin before writing: search KYM (`https://knowyourmeme.com/search?q=...`, curl with a browser User-Agent), then
     X (`search_posts_all` for the earliest post with the caption, `get_posts_by_ids` to follow `referenced_tweets` back to the root of
     a quote chain), then the Reddit post. If none of that documents a first post or creator, set `origin_confirmed: false` and say so.
   - Don't rewrite entries that already have text unless a fact was wrong. Text is written once and reused. If you correct one,
     update `checked` (this bumps the page's dateModified and sitemap lastmod).
6. **Deploy**:
   ```bash
   git add -A && git commit -m "Daily update $(TZ=America/Los_Angeles date +%F)" && git push origin main
   ```
   `git add -A` matters: each day adds a new `archive/<date>.html` and `data/archive/<date>.json`.
   GitHub Pages rebuilds in about a minute (`gh api repos/NotParagon/memestand/pages/builds/latest --jq .status` should say `built`).

### Ranking method (virality evidence score, in `tools/rank.py`)

| Signal | Points |
|---|---|
| X: best post's views (API impressions); if only likes are known, 10 × likes | 10 × log10(views); 1M = 60, 10M = 70 |
| TikTok: best post's views (read directly, or KYM-cited) | 10 × log10(views) − 5; 10M = 65 |
| Instagram: best post's likes (logged-out pages show no plays) | 10 × log10(likes × 10) − 5; 1M likes = 65 |
| YouTube: best video about the meme, only if ≥ 10,000 views | 10 × log10(views) + 5; 100K = 55, 1M = 65 |
| Reddit top-feed position (Reddit hides vote counts from anonymous feeds) | r/memes #1 = 62, r/dankmemes #1 = 60, −2 per rank |
| Combined reach (each platform capped at 75) | best + 0.10 × 2nd + 0.05 × 3rd |
| Each additional source with confirmed evidence (of the six, KYM included) | +3 (max +12) |
| Picked in a KYM editorial / Weekly Roundup / Meme-of-the-Month poll | +3 |
| X News trending story about it | +5 |
| KYM page views ≥ 50,000 | +5 |

- Each platform is normalized on its own scale (TikTok views are cheap, Instagram only shows likes, YouTube views are scarce),
  so one platform's raw counts can't dominate; the 75 cap stops a single giant post from swamping everything.
- Cross-platform presence is rewarded twice: a share of the 2nd/3rd platform's reach, and +3 per extra source.
- Ties keep candidate order.
- A meme may appear in more than one list. Big ones usually do.
- The red top story (lead headline) is chosen by the "Lead headline" rule below, not always the daily #1.

### Lead headline (rotates daily; no repeats within 7 days)

The big top story on the homepage (and on each `archive/<date>.html`) must be a different meme every day. `build.py` picks it
automatically (`choose_leads()` / `pick_lead()`); the daily, weekly and monthly top-10 lists stay ranked exactly as rank.py made them.

1. Candidates are today's daily top-10 in rank order, minus anything blocklisted, removed, or failing the legal rules
   (`tools/legal.py` `exclusion_reason`: flags, hard terms, minor check, unattributed allegations).
2. Drop every meme that was the lead on any of the previous 7 days (`data/lead_history.json`).
3. If a meme that is **new today** (in no earlier `data/archive/*.json` snapshot) is in the daily top 3, it leads.
4. Otherwise the highest-ranked remaining candidate leads.
5. If every candidate was a recent lead, fall back to the daily #1 (first one that passes the legal rules).

- `data/lead_history.json` maps date -> meme slug (the `data/meme_pages.json` slug). build.py writes today's entry, never changes
  past days, and seeds any day missing from it with that day's archived daily #1 (the old rule). **Commit it every day; never delete it.**
- The pick is deterministic for a given day: today's entry is recomputed only from earlier days, so a second `python3 build.py`
  gives no diff. build.py prints `lead <date>: <slug> (<reason>)`; check it before pushing.
- Don't hand-pick or hand-edit the lead. If the chosen lead needs a headline fix, fix the candidate in `data/candidates.json`
  and rerun rank.py + build.py. The kicker reads "TODAY'S LEAD MEME" (archives: "LEAD MEME OF <date>"), since the lead may not be #1.

### Daily rank labels (daily top 10 only)

`tools/rank_history.py`, called from `build.py`, adds a short note under each daily headline on the homepage and `/top-memes-today/`. The same note is on each `archive/YYYY-MM-DD.html`, worded so it stays true later ("New that day", "from the day before"). Weekly and monthly lists are unchanged. The lead-headline rule and the score in `tools/rank.py` are unchanged.

The note uses only `data/archive/YYYY-MM-DD.json` daily lists — one file per Pacific calendar day — and the stable meme-page slug (`data/meme_pages.json` `ids`). An hourly rebuild overwrites today's file and does not add a day. A candidate id that maps to an existing slug is the same meme.

| Note | When it is shown |
|---|---|
| **New today** | On this day's daily list, and not on the previous Pacific day's list. A return after a day off gets this note. It does not mean the meme has never ranked before. |
| **First time** | Shown with New today only when no earlier daily archive contains that slug, and every Pacific day from the first archive file through yesterday has a file. This is a first-ever daily identity. A gap in the archive blocks it. |
| **Up N / Down N / Unchanged since yesterday** | The slug was on yesterday's daily list. N is how many ranks it moved (rank 1 is best). |
| **N days at #1** | The slug was daily #1 on this day and on each previous Pacific day, walking backward one day at a time, and N is at least 2. A missing file or a day that was not #1 stops the walk and drops the old count. The first day of a run shows no streak note. |

If this is the first archived day, or yesterday's file is missing, the row gets no New / First time / movement note. A missing day is never filled in. Do not hand-write these notes. `python3 tools/test_rank_history.py` covers the first day, an unchanged #1, a broken #1 streak, a reentry, new-versus-first-time, up/down/unchanged, a missing archive, and the Pacific midnight / hourly boundary.

## Deploying with the GoDaddy domain

| Option | Cost | DNS work at GoDaddy | Daily-update path |
|---|---|---|---|
| **A. GitHub Pages** (recommended) | Free | Add 4 `A` records for `@` (185.199.108.153, .109.153, .110.153, .111.153) + `CNAME www → <user>.github.io` | `git commit && git push`; live in about 1 minute, free HTTPS |
| B. Cloudflare Pages | Free | Change the nameservers at GoDaddy to Cloudflare's (DNS then managed in Cloudflare) | `npx wrangler pages deploy . --project-name memestand` with an API token |
| C. Netlify | Free tier | Netlify DNS, or `A @ 75.2.60.5` + `CNAME www` | `netlify deploy --prod` with a token |
| D. GoDaddy cPanel / Web Hosting | About $6–12/mo extra | None (same account) | Upload by FTP/SFTP (`lftp mirror -R`) using hosting credentials |

**Recommendation: A, GitHub Pages.** It is free, gives automatic HTTPS, and handles static traffic spikes well.

- The domain stays at GoDaddy and only needs DNS records added. Nameservers don't move.
- The daily refresh becomes a single `git push`. That is the easiest thing for an automated job to do reliably.
- Cloudflare Pages is an equally good choice if you'd rather move DNS to Cloudflare, since it also adds CDN and analytics.
- Avoid paying GoDaddy for cPanel hosting just to serve a static page.

One-time setup (needs Roger's accounts, nothing has been changed yet):

1. Create a GitHub repo, e.g. `memestand`, and push this folder. `raw/` can be excluded.
2. Enable Pages: Settings → Pages → Deploy from branch `main`, root. Set the custom domain to `memestand.com` and tick Enforce HTTPS.
3. In GoDaddy:
   - Go to My Products → memestand.com → DNS.
   - Delete the default "Parked" `A @` record.
   - Add the four `A @` records above and `CNAME www → <github-user>.github.io`.
4. Wait for DNS (minutes up to about 1 hour), then the site is live at https://memestand.com.

## SEO and AI-assistant discovery (all automatic in build.py)

Every `python3 build.py` regenerates all of this from `data/memes.json`, so no manual SEO step is needed each day:

- **Head tags** on every page: keyword title, meta description naming today's #1, canonical `https://memestand.com/...`,
  Open Graph + Twitter `summary_large_image` (og:image = today's #1 local thumbnail as an absolute URL, or `og-default.png`
  when #1 is a text card), favicon links, Atom feed link, `lang="en"`.
- **Headings**: one `<h1>` per page (masthead + tagline), `<h2>` "Top 10 Memes Today / This Week / This Month", `<h3>` per meme.
  Alt text on every image is "<Title-Case headline> meme - #N today on MemeStand".
- **JSON-LD** (`@graph`): Organization, WebSite, CollectionPage (dateModified = build time), and an ItemList per top-10 list
  (ListItem position / name / url / image). Archive pages add datePublished and a BreadcrumbList.
- **Pages**: `/top-memes-today/`, `/trending-memes-this-week/`, `/best-memes-this-month/` (with the evidence notes),
  `/archive/YYYY-MM-DD.html` (one per day; same-day rebuilds overwrite only today's), `/archive/`, `/about.html`.
- **Crawl files**: `sitemap.xml` (lastmod per URL), `robots.txt` (allows everyone incl. GPTBot, OAI-SearchBot, PerplexityBot,
  Google-Extended, ClaudeBot, Applebot-Extended, CCBot...), `llms.txt` (site summary + today's three lists in Markdown),
  `feed.xml` (Atom, newest 60 daily #1s).
- The old 30-minute `<meta http-equiv="refresh">` was removed: content changes on the ~3-hour cadence above, and Bing and accessibility
  guidelines treat timed refreshes as a negative. Don't add it back.
- Headline title-casing for titles/descriptions uses `ACRONYMS` / `SPECIAL` in build.py; add a word there if one comes out wrong (e.g. "Gpu").

### SEO checks (run before each push; takes seconds)

```bash
python3 build.py && python3 build.py && git status --short   # 2nd run must change nothing beyond the 1st (idempotent)
python3 - <<'PY'
import json, pathlib
from lxml import etree, html
for p in pathlib.Path('.').rglob('*.html'):
    if 'raw' in p.parts: continue
    d = html.fromstring(p.read_text())
    [json.loads(s.text) for s in d.xpath('//script[@type="application/ld+json"]')]   # raises if JSON-LD is broken
    assert len(d.xpath('//h1')) == 1 and all(i.get('alt') for i in d.xpath('//img')), p
    if p.parts[0] == 'meme':   # every meme page: FAQPage whose questions are the first two H2s
        g = json.loads(d.xpath('//script[@type="application/ld+json"]')[0].text)['@graph']
        faq = [n for n in g if n.get('@type') == 'FAQPage']
        assert faq and all(q['@type'] == 'Question' and q['acceptedAnswer']['text'] for q in faq[0]['mainEntity']), p
        assert [h.text_content() for h in d.xpath('//h2')][:2] == [q['name'] for q in faq[0]['mainEntity']][:2], p
etree.parse('sitemap.xml'); etree.parse('feed.xml')
print('ok')
PY
```
After pushing: `curl -s https://memestand.com/ | grep -c 'application/ld+json'` should print 1.

## Meme pages (`/meme/<slug>/`, `/memes/`, store: `data/meme_pages.json`)

Every meme that has ever ranked gets a permanent page at `https://memestand.com/meme/<slug>/`. The H1 is
"<Meme name> meme: what it means and where it came from"; the `<title>` is "<Meme name> Meme: Meaning & Origin | MemeStand"
(names ending in "memes"/"trend" are used as-is) and the meta description starts "<Meme name> meme meaning: <first sentence>".
The page shows the thumbnail, then H2 "What does the <name> meme mean?" (explainer), H2 "Where did the <name> meme come from?"
(origin, plus the note "The original creator of this meme hasn't been confirmed." when `origin_confirmed` is false), an optional
H2 "How to use it" (the `how_to_use` captions), first- and last-seen dates on MemeStand, the best rank per list, links to every archive day it appeared on, sources and related memes.
`/memes/` is the A–Z index. Every headline on the home, period and archive pages links to the meme page; the thumbnail
and "View original" still link to the source. The pages are also listed in `sitemap.xml` and `llms.txt` automatically.

**Store format** (`data/meme_pages.json`, keyed by slug, sorted; build.py rewrites it deterministically):
```json
"sam-altman-ram": {
  "name": "Sam Altman RAM",            // display name; the H1 adds " meme" unless the name ends in meme(s)/trend
  "ids": ["altman-ram"],                // candidate ids that map to this page
  "status": "full",                     // "full" = explanation + origin backed by sources; "short" = only what the source shows
  "source_url": "...", "kym_url": "..." or null,
  "explainer": "2-4 sentences, plain English: what the meme shows, what the joke means, how people use it",
  "origin": "1-2 short paragraphs: who posted it, where, when (only if verified) and how it spread",
  "origin_confirmed": true,             // true only if a source documents the first post/creator; false = unknown (page says so); null = not researched yet
  "how_to_use": ["example caption", "another"],  // 0-2 short example captions in our own words; [] to skip the section
  "sources": [{"name": "The Verge: ...", "url": "..."}],   // every source the text relies on (the ranked post is added automatically)
  "related": ["other-slug"],            // optional; build.py adds memes that shared the same lists
  "written": "YYYY-MM-DD",
  "checked": "2026-11-03T23:50:00-08:00"  // when the text was written or last reviewed (PT, real time); feeds dateModified + sitemap lastmod
}
```
- **Slugs are permanent.** build.py makes a slug from the meme's name (or id), dedupes it (`-2`, `-3`) and stores it. Never rename a slug or
  reuse one for a different meme. If a meme returns under a new candidate id, add that id to the existing entry's `ids` instead of making a new page.
- Optional candidate fields `name`, `explainer`, `origin` and `kym_url` in `data/candidates.json` pass through `rank.py` into `memes.json`,
  and build.py copies them into an empty store entry. They never overwrite text already in the store.
- **How to write them** (same rules as "Legal rules" below):
  - Use only facts in the data or in a source you actually opened: the ranked post, the KYM entry, or a primary source (transcript, the post itself).
    List each one in `sources` (KYM entry, the original post, the Reddit/X post). Link the original post or KYM. Never invent a fact, number,
    date or URL; view counts come from the X API or the cited source and are phrased "per X's public counts" / "per KYM".
  - Write everything in your own words. Never copy KYM (or any source) sentences. Concise, factual, friendly, no fluff.
  - "What it means" is your own short, original explanation (don't copy KYM text). Explain the joke format and how people use it.
  - "Origin" is neutral and factual: who posted what, where, and when, per the source. **Never invent an origin.** If it isn't documented,
    say what the ranked post shows, say plainly that the original creator hasn't been confirmed, and set `"origin_confirmed": false`
    and `"status": "short"`. For a remix of an old template (Gru's Plan, Two Paths...), give the template's documented origin with its
    KYM link, and mark the specific caption unconfirmed unless its first post is documented.
  - `"status": "full"` only when `origin_confirmed` is true.
  - No unverified claims about real people. Frame allegations as allegations attributed to their source ("per KYM"). Don't name private
    people or people only connected to an allegation. Quote real people only from the primary source.
  - Don't publish Roger's full name or address, and don't use the Drudge name.
- `FAQPage` JSON-LD (inside the page's single `@graph`) is added to every page that has both `explainer` and `origin`. Its questions are
  the visible H2s word for word and its answers are the visible text (plus "How do you use the <name> meme?" when `how_to_use` is set),
  so it always matches what readers see. Pages without text get no FAQ and say they are deliberately short.
- Blocked memes (`data/blocklist.json`) get no page: build.py drops their store entry and deletes `meme/<slug>/`. Archive pages are never deleted.
- og:image on meme pages follows `OG_USE_MEME_THUMB` (currently off, so `og-default.png`).

## Legal rules (enforced in tools/legal.py, tools/rank.py and build.py; follow them on every refresh)

Not legal advice. These rules keep the site's copyright, defamation and content risk low. They live in code so they survive rebuilds.

**1. Takedowns / DMCA: `data/blocklist.json`**
- When a takedown request or DMCA notice arrives (GitHub issue or email), act within 1-2 days. Add an entry to `entries`:
  `{"id": "<candidate id>", "url": "<source or image URL>", "title_contains": "...", "reason": "DMCA notice from X", "date": "YYYY-MM-DD"}`
  Any one of `id`, `url` / `urls`, or `title_contains` is enough; use the most specific one.
- Then run `python3 tools/rank.py && python3 build.py` and push. rank.py drops the candidate from candidates.json and deletes its thumbnail.
  build.py replaces the item with "[REMOVED IN RESPONSE TO A TAKEDOWN REQUEST]" on every page, archives included, and scrubs it from `data/archive/*.json`.
- Never remove a blocklist entry unless a valid counter-notice restored the item (process on /dmca.html). Keep a private log of notices
  (date, sender, item, action) outside the public repo.
- The image stays in git history. For a serious claim, Roger can rewrite history or ask GitHub Support.
- Repeat-infringer rule: if one source account gets 2+ valid notices, stop featuring that account (add its posts and/or a note in candidates).

**2. Headlines must be neutral and attributed**
- Headlines describe the meme and the reaction, not facts about people. Don't write "X DID Y" about a real person unless it is a documented,
  verifiable fact, and even then attribute it ("PER KYM", "PER <outlet>").
- Allegations (affair, cheating, fraud, crime, abuse, racism...) must be framed as allegations, with the source:
  `H3'S ETHAN KLEIN CHEATING ALLEGATIONS SPAWN A MEME FACTORY, PER KYM`, not `ETHAN KLEIN AFFAIR SCANDAL`.
- Quote what people actually said, verified at the primary source (transcript, the post itself). Don't paraphrase it into something stronger.
- Label jokes as jokes: `X USERS JOKE THAT KEN PAXTON 'EATS SALSA...'`, `ELON MUSK JOKES ABOUT...`.
- rank.py **excludes** a candidate whose title or card text uses an allegation word without an attribution word (per / alleged / accused /
  memes about / jokes / reportedly...). Set `"headline_reviewed": true` only after you have checked the wording against these rules.
- Notes ("Why it ranks") follow the same rules.

**3. Content exclusions** (also published on /about.html#policy)
- Add `"flags": [...]` to a candidate to exclude it: `nsfw`, `sexual`, `hate`, `demeaning` (mocks race, ethnicity, national origin,
  religion, sex, orientation, gender identity, disability), `minor`, `graphic`, `self-harm`, `harassment`, `doxxing`, `private-person`, `defamatory`.
  Add a `flag_note` explaining why.
- Automatic: hard terms (nsfw, porn, nude, gore, suicide, doxxing...) exclude a candidate. Words suggesting a child (kid, teen, baby,
  "12-year-old"...) exclude it until you confirm no minor is the subject and set `"minor_reviewed": true`.
- Never feature memes about a private individual who didn't choose publicity (random people filmed in public, leaked DMs) unless
  they have clearly embraced it. When in doubt, leave it out.

**4. Images and attribution**
- Thumbnails: max 400 px on the longest side, re-encoded JPEG with EXIF/GPS/ICC metadata stripped. rank.py enforces this on every run for
  all files in images/ (`normalize_images`), so never commit a larger or raw image.
- Every item shows a credit line ("posted by u/<user> on r/<sub>", "posted by @handle on X", "image via Know Your Meme") plus "View original".
  rank.py fills it in automatically (Reddit authors from raw/reddit.json). Set `"credit"` on a candidate to override it, e.g. with the real creator.
- `"image_policy"` per candidate: `local` (default, small thumbnail), `hotlink` (show the platform's own image URL, nothing stored here; use it
  for professional or agency photos), `none` (text card only; use it for paparazzi or stock photos, screenshots of private messages,
  or anything a rights holder is sensitive about).
- Social preview cards (og:image) use our own `og-default.png`, not someone else's meme (`OG_USE_MEME_THUMB = False` in build.py).
- Don't add other JavaScript embeds (X widgets.js etc.) without first updating /privacy.html: they set third-party cookies.
  The Cloudflare Web Analytics beacon is the only allowed script (cookieless, disclosed on /privacy.html).

**5. Names and trademarks**
- Use X, Reddit, Know Your Meme only to name sources. Never imply partnership, and never use their logos.
- Don't call the site "Drudge-style" or use the Drudge Report name.
- The footer non-affiliation line and the "memes (c) their respective owners" notice are generated. Keep them.

**6. Legal page settings** (`LEGAL` dict at the top of build.py)
- `contact_email` / `dmca_email`: both `hello@memestand.com`. Contact email everywhere is hello@memestand.com. Don't change it or add other addresses unless Roger asks.
- `dmca_agent_registered`: set True after Roger registers the DMCA designated agent at https://dmca.copyright.gov (renew every 3 years).
- `governing_law`: "California" is a placeholder until Roger confirms it.
- Never publish Roger's full name, home address or phone on the site.
